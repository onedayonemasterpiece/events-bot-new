## P2 — пустая строка между частями длинного VK-дайджеста

**Прямое новое требование владельца:** «при генерации текста дайдеста дополнительно пустую строчку вставляли между абзацами, иначе тяжело читается большой текст».

Целевой существующий сценарий: VK-дайджест экскурсий в «Ух ты, Калининград!» с текстом Sol/Google. На актуальном `main@d7560105` его сборка расположена в [`guide_excursions/visual_digest.py::_assemble_vk_narrative`](https://github.com/onedayonemasterpiece/events-bot-new/blob/d7560105066abc0a0480911b606d56f33eaec096/guide_excursions/visual_digest.py#L2521-L2629), вызов — [`build_visual_digest_vk_text`](https://github.com/onedayonemasterpiece/events-bot-new/blob/d7560105066abc0a0480911b606d56f33eaec096/guide_excursions/visual_digest.py#L2632-L2687). Структурные абзацы LLM приходят как `narrative["paragraphs"]`. **Между разными экскурсиями уже вставляется `"\n\n".join(blocks)` (строка 2617), значит нельзя просто добавить этот же separator ещё раз сверху.** Плотность создаёт сборка **внутри** одной экскурсии: `blocks.append("\n".join([heading, names(body), *lines]))` (строка 2612), а `collapse_ws(body)` стирает внутренние переносы, если модель прислала их как часть одного текста.

**Минимальная правка в одном существующем assembler:** отделять заголовок, редакционный рассказ и блок расписания/цены/ссылки **ровно одной пустой строкой**, оставляя строки расписания друг под другом без пустых строк; разные экскурсии и так отделены `\n\n`. Это formatting-only: не менять сам prompt, значения дат, имена, упоминания `[id...|...]`, URL, цену, хештеги, состав экскурсий и изображение. Не запускать отдельный редактор/LLM для переносов и не делать глобальное `text.replace("\n", "\n\n")` — оно испортит служебные строки/разметку.

**Контрольный пример** (синтетический, только оформление):

```text
ДО:
ПРОГУЛКА ПО РАЙОНУ
Длинный связный рассказ об истории места и маршруте.
21 ноября, 11:00
💳 1200 ₽
🔗 Запись: ...

ПОСЛЕ:
ПРОГУЛКА ПО РАЙОНУ

Длинный связный рассказ об истории места и маршруте.

21 ноября, 11:00
💳 1200 ₽
🔗 Запись: ...
```

**RED/GREEN:** добавить **один адресный тест** в [`tests/test_guide_visual_digest.py`](https://github.com/onedayonemasterpiece/events-bot-new/blob/d7560105066abc0a0480911b606d56f33eaec096/tests/test_guide_visual_digest.py), используя существующую `EDITION_349` и мок `ask_vk_narrative`. Проверить точные `\n\n` между heading/текстом/логистикой для двух экскурсий и отсутствие `\n\n\n` в середине. Убедиться, что `[id...|...]`, `[https://...|Запись]`, даты/цены/хештеги не изменились, компактный fallback по-прежнему доступен. Проверить итоговый VK post text (preview/test), **не только сырое LLM JSON**. **Бюджет:** до 10 строк production, один существующий тест, без новых флагов/валидаторов. Если правильная правка требует больше — назвать точную причину, не добавлять архитектуру.

Визуальные карточки и Telegram-короткая подпись используют другие форматтеры; не менять их автоматически без доказательства того же дефекта. Для отдельного длинного Telegram-дайджеста сначала найти соответствующий consumer, не перетягивать эту правку на все публикации.

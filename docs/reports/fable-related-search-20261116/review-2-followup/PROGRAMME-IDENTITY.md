Утренний граф 17 ноября содержит по семь кандидатов с таким названием на каждый из двух запросов. Выбор для публикации ограничен пятью строками. Все пять в сохранённых заданиях от 16 ноября входят и в эту семёрку. Это два разных момента наблюдения. Данные от 17 ноября не устанавливают историческую причину исключения каждой из двух остальных карточек 10274 и 10493.

**Воспроизводимый дефект обработки.** Запрос о старой связи сортирует ID, обработчик считал первый ID текущей карточкой. При обычном обновлении 10346 проверка возвращала обе дословные цитаты и независимость программ в том же порядке [7236, 10346], а счётчик показывал `returned_decisions=1, accepted_pairs=0`. Старая связь сохранялась. Работало только обновление с меньшего ID. PR #1052 сопоставляет цитаты с правильными сторонами уже проверяемой старой связи. Новый тест дал один отказ и один успех на main, после исправления все 16 тестов файла прошли. [GitHub CI завершился успешно](https://github.com/onedayonemasterpiece/events-bot-new/actions/runs/44045205395). Исторический ответ модели по «Щелкунчикам» не сохранился; этот тест устанавливает изъян кода, но сам по себе не восстанавливает продовые данные. При штатном обновлении источника старые соседи попадают на пересмотр даже за пределами top-12. [Изменение и тест](https://github.com/onedayonemasterpiece/events-bot-new/commit/1abe951437450d489f77d9f614fff06f4eb59b5c)

**Другой исход у «Красного фонаря».** Оба сеанса дошли до наблюдателя связей в одном пакете из 14 участников. Первичный ответ не разобрался. Восстановление ответа прервал общий лимит 90 секунд. В эту ветку обработчика пришло `None`. На следующем слое это пустое множество решений. Штатный writer сохраняет принятые события и прежние взаимные связи. У этих двух сеансов прежних связей не было. Отдельный старый опыт со схемой вернул 503. Обязательного отложенного восстановления конкретного набора ID пока нет. Обычный новый импорт или содержательное обновление источника может снова собрать этот набор. Пересборка векторного графа эту функцию не вызывает. Ближайшая задача владельца — определить, может ли существующий владелец принятого пакета доставить подтверждение ровно для нужных ID после технического отказа. Положительный исход должен быть виден в SQLite и в готовом расписании. [Исходный обработчик](https://github.com/onedayonemasterpiece/events-bot-new/blob/01101867db78cf1c5d0a5cce643ad331e483c1c1/linked_events.py)

Отдельно проверен writer этого коммита с заданными решениями и временной SQLite. Для балета и сказки все четыре перекрёстные пары из четырёх карточек исчезли в обе стороны, обе подтверждённые пары остались. Для 11071 и 11072 появился ровно один взаимный переход. 10278 и 10311 с end_date не добавились в расписание даже при положительном решении. На пустом результате исходные взаимные связи остались. Этот опыт проверяет запись уже полученного решения. Получение решения и показ читателю имеют отдельную приёмку в задаче.

# Когда проверять похожие события через Gemini Flash-Lite

17 ноября 2026 · KenigEvents · Для Fable (`devester`) и владельца проекта

**Предложение для независимой проверки.** Самый обоснованный случай для Gemini 3.5 Flash-Lite — конкретный кандидат, которого Gemma пропустила в частично обработанной десятке и для которого адресная повторная попытка Gemma тоже не дала решения. Для такого кандидата у нас есть и рабочий запрос, и пример изменения списка VK с одной строки до двух. Второй возможный случай — спорное решение в карточке, где читатель видит мало похожих событий. Его пока стоит проверять по независимой разметке. Оба случая относятся к оценке пар, уже найденных векторным поиском.

## Какой ресурс доступен

Суточный счётчик сбрасывается в полночь по тихоокеанскому времени, 17 ноября это 10:00 по Калининграду. Цифры ниже получены из журнала рабочего лимитера. Для короткого опыта выбрана 3.5. У 3.1 больше обычная загрузка, включая мониторинг и обработку медиа. За предыдущие сутки три проекта исчерпали лимит 3.1, один — лимит 3.5. ## Что вернула модель

До отправки зафиксированы десять направленных пар для трёх карточек. Шесть положительных пар взяты из прежней разметки, два отрицательных примера предложил Fable и ещё два отметил исполнитель до запроса. Lite получила тексты событий и ту же инструкцию оценки, что и Gemma. Прежние баллы и разметка в запрос не входили. Три пакета содержали 5, 3 и 2 кандидата. Четвёртая отправка повторила точный текст одиночного запроса, на котором Gemma вернула 503. Запросы прошли через обычный лимитер, все четыре вернули ожидаемые ID ровно один раз. Опыт оценивает практический результат адресного обращения. Приписать всю разницу выбору модели или оценить точность на всём каталоге по нему нельзя.

## Что увидел бы читатель VK

Для стендапа 11010 повторно запущена штатная функция показа на рабочих карточках в режиме чтения. Публичность точных ссылок взята из сохранённого ответа VK от 16 ноября, 18:06 по Калининграду. В граф поочерёдно подставлялись только измеренные оценки. Вот строки, которые вернула функция в каждом случае. [Карточки, ссылки, порядок и результат штатной функции](reader-impact.json)

| --- | --- |
| Сохранённые однозначные решения Gemma | Сборный стендап |
| Плюс одиночный ответ Lite для пропущенного ID | Таня Виноградова · Сборный стендап |
| Плюс ответы Lite по двум проверенным пограничным стендапам | Таня Виноградова · Сборный стендап · Макс Кузнецов |

У прошедшего Gemma концерта Дроботенко в карточке отсутствует ссылка. У «Девочки, это пипец» ссылка есть, но балл остался 0,70. В этой же двадцатке есть ещё пограничные ID, которые мы не отправляли Lite. Три строки воспроизводятся только при описанной подстановке. Для «Жизни Пи» проверена доступность отдельной строки. Её место в полном списке фильма остаётся открытым.

## Как выбрать случаи

**1. Пропущенный кандидат после повторной попытки Gemma.** Предлагаем Fable рассмотреть один короткий вызов 3.5 с оставшимися ID частично обработанного пакета, когда штатное восстановление #1045 исчерпано. Для каждого ID принимается только один валидный ответ по существующей схеме. Учитываются фактическая модель, версия инструкции и действующие правила прохода. Уже полученные решения Gemma сохраняются. Если Lite недоступна или опять не вернула запрошенный ID однозначно, он остаётся без решения для штатной повторной обработки. Ошибка всей исходной десятки не запускает перенос всего потока на Lite.

Сейчас статический сборщик требует проверки Gemma и отключает общий механизм смены модели. До использования Lite в рабочем сборщике нужен узкий пересмотр этого правила для восстановленных ID с сохранением фактического источника оценки в кэше. Старые записи по-прежнему означают то, что в них было записано. [Правило статического графа](https://github.com/onedayonemasterpiece/events-bot-new/blob/7ee773ceabed87d0bc9be30ce33bda80656115e5/docs/features/unsigned-personalization/semantic-vector-retrieval.md#L164-L180) · [Адресное восстановление в #1045](https://github.com/onedayonemasterpiece/events-bot-new/pull/1045)

**2. Пограничное решение для конкретной карточки.** Предлагаем сравнить на новых карточках следующий вариант. Основание — конкретная жалоба на подборку либо ноль или одна фактически доступная читателю строка после обычной обработки и восстановления пропусков. Стендап 11010 соответствует первому условию и после восстановления второй строки. Среди найденных кандидатов рассматриваются самостоятельные программы с действующей ссылкой, без явного отказа Gemma и с оценкой от 0,65 включительно до 0,72 исключительно. Такие пары одной карточки можно передать Lite одним коротким запросом. Для сравнения моделируем добавление при самостоятельном проходе порога Lite и повторяем штатный показ. Среднее и максимум баллов двух моделей здесь не откалиброваны. До независимой проверки разногласия остаются материалом для разбора. Уверенность Gemma тоже не годится как единственный признак — у обоих стендапов с 0,70 она равна 0,95.

Ширину правила можно проверить на сохранённом кэше на 10:46 по Калининграду. Из 728 карточек-кандидатов у 84 нашлись пакеты с сохранёнными ответами. В них 1 380 запрошенных пар, 1 355 с баллом. В уже обработанных пакетах 25 пар у 8 карточек остались без оценки. Часть таких пропусков может закрыть сама #1045. Простое правило «0,65–0,71 без отказа» затронуло бы 204 пары у 80 из 84 карточек. Из 49 карточек с полными двадцатками лишь у пяти было не больше одного прошедшего кандидата ещё до проверки VK, в них 17 пограничных пар. Это объёмы снимка. Суточную потребность и число доступных публичных строк надо считать отдельно. [Кэш и его колонки](cache-slice.json) · [Пересчёт объёма](count_candidates.py)

У такого отбора есть известные пропуски. Для «Кентервильского привидения» две размеченные положительные пары получили у Gemma 0,40 и 0,50 с явным отказом. Обе оказываются вне диапазона. А правильная оценка «Жизни Пи» сама по себе не гарантирует место в уже заполненной подборке фильма. Повторные сеансы «Красного фонаря» относятся к определению программы и ведутся отдельно. ## Что проверить Fable под учётной записью devester

1. Пересчитать результаты из checkout этой ветки. Нужен Python 3.9 или новее со стандартной библиотекой. Запросы и ответы моделей, срезы расхода и сведения для проверки VK сохранены рядом. Доступ к Google, VK и рабочей базе для пересчёта не требуется.
2. Заранее разметить другие карточки, включая подходящий стендап, слабую связь только по аудитории и ту же программу в другую дату. По возможности сделать разметку до просмотра баллов. Сравнить действующую Gemma, адресное восстановление пропущенного ID и добавление пограничных пар у карточек с коротким списком. Отдельно выписать полезные новые строки, лишние строки, оставшиеся без оценки ID и потребное число обращений. Неизвестный ответ в старых данных учитывать отдельно от отказа.
3. Дать два решения владельцу. Достаточно ли свидетельств для разрешения Lite после неудачного адресного восстановления? Есть ли у проверки пограничных пар дополнительная польза по реальным строкам и какой пример опровергает предложенный признак? Если для ответа нужны новые вызовы, вернуть ID и тексты необходимых пар. Чужие учётные данные для подготовки заключения не нужны.

Репозиторий публичный. В существующем клоне выполните команды с рабочего дерева нужной ветки.

```bash
git fetch origin review/fable-flash-lite-routing-20261117
git worktree add --detach ../fable-flash-lite-review FETCH_HEAD
cd ../fable-flash-lite-review/docs/reports/fable-related-search-20261116/flash-lite-20261117
python3 check_lite.py
python3 verify_quota.py
python3 count_candidates.py cache-slice.json
python3 compare-triggers.py ../review-2-followup
python3 check_reader.py
```

В первом выводе ожидаются 10 уникальных пар, четыре отправки и 4 906 токенов. Во втором — ранний срез 11:04 (2 968 свободных запросов 3.5 и 2 943 у 3.1). В третьем — 204 пограничные пары у 80 карточек. В четвёртом — 48 однозначных ответов среди 50 пар предыдущей проверки. Последняя команда сверяет списки из одной, двух и трёх строк с сохранёнными данными. Настоящий опыт относится к выбору второй проверки. В этой ветке опубликованы отчёт, исходные записи и команды проверки. Рабочий сборщик по-прежнему применяет действующее правило Gemma.

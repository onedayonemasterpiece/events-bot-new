# Static listing visual lab

Канонический проектный workflow для визуального исследования и приёмки списочных карточек KenigEvents находится в `.codex/skills/static-listing-visual-lab/SKILL.md`.

Использовать для Главной, «Для вас», «Популярного» и high-intent списков, когда решение зависит от реальных OCR-афиш, ориентаций, mixed galleries, smart crop, наложения текста, адаптивных прототипов или независимой formation/validation через agy. Артефакты исследования хранятся только в `artifacts/codex/`.

Метрика «подходящее событие в пределах 20–30 карточек» трактуется как накопительные уникальные касания по всему пути между страницами и блоками, а не как обязательная длина одной ленты. Каждый визуальный вариант обязан иметь короткий стабильный ID/название, видимые прямо на макете и повторённые в имени файла, подписи и таблице сравнения.

Desktop-кандидаты проверяются на реальных p95/p99/max заголовках и проходят только при скруглённом edge-to-edge media, отсутствии декоративных полей/blur-fill, конечном наборе aspect-токенов для подтверждённых crop-safe фото и fail-closed обработке OCR/unknown/low-res. Канонический заголовок остаётся H1/structured-data/source-of-truth; видимый фактосохраняющий `browse_title` допустим только для полностью провалидированного хвоста переполнений. Desktop-нормализация не переносится на mobile автоматически: мобильная гипотеза проверяется отдельно как линейная лента с компактными навигационными блоками.

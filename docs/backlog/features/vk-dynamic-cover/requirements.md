Обновление обложки Вк сообщества в соответствии с актуальной информацией или промо

Выяснилось, что есть общая картинка сообщества (широкая 1920×768 px) для декстопа

А для мобильный версии есть живые обложки (до 5 штук)

Цель, не теряя узнаваемость подсвечивать самые важные фундаментальные события или промо

В первую очередь подсвечивать фестивали, например по состоянию на июнь 2026 идут фестивали:
- 80 историй о главном
- Кантата
- Русская музыка на Балтике

Можно было бы их подсветить.

Обложка должна быть автоматически генерируемая как широкая, так и мобильные живые обложки, которые автоматически сменяются Разрешение: 1080 × 1920 пикселей

# Стиль
Современный стиль, лёгкий и одновременно контрастный и динамичный

Чтобы совсем не терять стилистическую связку с изначальным логотипом сообщества, прикладываю его /home/dev/projects/events-bot-new/docs/backlog/features/vk-dynamic-cover/photo_2025-02-02_11-08-25.jpg

Сильные палитры и цветовые пары можно взять из engagementcard для публикации дайджеста экскурсий, шрифты тоже оттуда

Должны использоваться акцентные компоненты для формирования изображений, подразумевающие CTA или даты или периоды, в общем ключевую информацию

Для живых иллюстраций используем подход когда сохраняется связь визуала сообщества 20% и одновременно добавляется основная иллюстрация про например фестиваль.

Для широкой основной картинки лучше использовать разделение, например диагональные разделители

Ещё как вариант использовать несколько горизонтальных строчек, например идёт три фестиваля и информацию о них можно разместить построчно название, даты и где проходят

При диагональных разделителях можно показать несколько фестивалей или событий каждый в своей ячейке, одна ячейка может быть посвящена сообществу.

При диагональном разделении неплохо использовать фирменные цвета фестиваля и фирменный логотип. Нужно разработать схему извлечения логотипа с сайта фестиваля например.

# механика
Обложка меняется строго временно, и через неделю после установки может меняться в стандартную автоматически.

В обложку информация может попадать через промо, например фестиваль заводится в промо и далее активность показывать на обложке.

стоит сделать в боте команду /cover которая позволяет управлять, включать и выключать даже несмотря на включённые промо

И показывать историю смен.

Если у фестиваля есть Вк, то можно оттуда вытаскивать логотип.
Также нужны футажи, которые могут быть показаны вместо заливки под информацией о фестивале в блоке о фестивале, для этого у фестиваля должны быть иллюстрации. Проработать как их получать, вероятно из постов, возможно этот механизм уже работает.

# MVP
Показывать в нескольк строчек основные фестивали
Тебе нужно сохранить локально имеющуюся обложку как дефолт.
Так как механизм полноценного мониторинга фестивалей сейчас не работает, вероятно нужно сейчас разработать упрощённый минималистчный инструмент мониторинга фестивалей в целях промо и простого базового наполнения фестивальной страницы в телеграф, публикации какой-то базовой информации в https://vk.com/kenigeventsofficial в виде постов о фестивалях (важно чтобы не было спама надо видеть когда был последний пост о фестивале и тогда ставить в отложку на следуюшие сутки публикацию), вынеси потом документацию в отдельную фичу лайт версию мониторинга фестивалей только для общей информации
- Название фестиваля
- Сайт и соцсети фестиваля
- Логотип и айдентика фестиваля (цвета например)
- Период проведения фестиваля
- Локации фестиваля
этот MVP может проходиться по фестивальной очереди, которая у нас потихоньку накапливается и помечать что был лайт анализ. В принципе этой информации должно быть достаточно чтобы линковать события с фестивальной страницей и на фестивальной странице показывать все события фестиваля.

Важно: текущий Kaggle Universal Festival Parser перед использованием в light-monitor нужно
проверить и не запускать как полный проход по очереди. В коде/доках он всё ещё выглядит как
устаревший parser version 1.0.0 с Gemma 3-27B-ориентацией. Даже при наличии token-bucket
лимитера для MVP нужны жёсткие ограничения: whitelist фестивалей, `--limit`, общий timeout,
dry-run, сохранение `rate_usage.json`, fail-fast при quota/rate-limit и отдельная проверка
актуальных GoogleAI лимитов. Для 80 историй о главном + Кантата сначала достаточно лёгкого
deterministic enrichment без массовых LLM-запросов: VK/social links, логотип, базовая палитра,
период, локации и привязка event.festival к строке Festival.

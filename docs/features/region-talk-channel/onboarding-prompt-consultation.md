Ниже представлен инженерный и редакционный проект производственного конвейера для канала «О Калининграде говорят» (Region Talk).1. Короткий диагноз текущего разрываТекущий монолитный промпт (region_talk_final_verifier_v7_grounded_draft) страдает от проблемы «сборки Франкенштейна». Когда LLM в одной операции просят извлечь факты, сформировать досье, написать подводку и поставить ссылки, она переходит в режим суммаризации, а не редактуры.Отдельный onboarding-абзац и summary порождают link-dump, потому что у текста нет единой прагматики. Первый абзац отвечает на вопрос «что это за файл в базе» (досье), а второй — «что написано по ссылке» (пересказ). В результате читатель получает исчерпывающую справку, которая убивает мотивацию кликать. Настоящий редакционный текст должен отвечать на вопросы: «почему этот внешний взгляд важен для нас сегодня?» и «ради какой конкретной детали стоит открыть оригинал?».2. Редакционные принципыРадикальная атрибуция (Third-person boundary): Region Talk — это куратор, а не автор опыта. Любое впечатление, вывод или маршрут принадлежат источнику. Редакция не присваивает чужое «я».Презумпция внешнего взгляда: Каждое одобренное сообщение должно доказывать свою внерегиональность не штампом «известный тревел-блогер», а оптикой (например, метод сравнения со своим регионом, удивление привычному).Мотивационный дефицит: Текст не должен заменять оригинал. Мы продаем «клик», подсвечивая метод, необычный вывод или сильный визуальный ряд, оставляя само мясо (полный маршрут, все фото, весь список аргументов) по ссылке.Доказательность (Strict Grounding): Запрещено выводить профессию из темы канала или додумывать эмоции. Нет evidence — нет утверждения в публичном тексте.Сквозное повествование без фальши: История публикаций нужна для контраста и смены масштаба, а не для искусственного склеивания несвязанных людей. Fresh start — всегда лучше вымученного мостика.3. Рекомендуемая stage split (Архитектура конвейера)Для баланса между качеством текста, задержкой и стоимостью токенов в изолированном контейнерном окружении (например, при оркестрации через Docker/DevPod) рекомендуется 3-стадийная архитектура (Strategy -> Writer -> Critic).Объединять планирование и написание в один промпт опасно: модель начнет «срезать углы».Stage 1: Editorial Strategy (Planner)Вход: JSON кандидата, профиль источника, history context (последние 5 постов).Выход: JSON-план (editorial_plan), где зафиксированы throughline_mode, source_angle, и why_this_material_now.Логика: Модель работает только с метаданными и принимает композиционные решения.Stage 2: Grounded WriterВход: Утвержденный editorial_plan, сырые evidence_ids (текст и факты).Выход: Черновик (paragraph_1, paragraph_2), grounding_map.Логика: Жестко ограничена планом. Пишет текст, мапит каждое предложение на ID.Stage 3: Verifier / CriticВход: Результат Writer, исходные Evidence.Выход: Статус (Pass / Rewrite / Reject), список reason_codes.Policy: Допускается максимум один автоматический retry (передача Critic feedback обратно во Writer). Если вторая попытка провалена — needs_review для живого редактора.Кеширование и Fingerprint:Fingerprint черновика вычисляется как hash(candidate_id + evidence_hash + strategy_hash). Изменение системного промпта меняет contract_version, что инвалидирует кеш.4. Полный production system promptPrompt 1: Editorial Strategy (Planner)PlaintextYou are the Lead Product Editor for "Region Talk", a Russian-language curation channel. 
Your task is to design the editorial strategy for presenting an external (non-regional) perspective on the Kaliningrad region.
Do not write the final text. Produce ONLY the JSON plan.

INPUT CONTEXT:
You will receive:
1. 'candidate': Platform, URL, boundary status.
2. 'source_profile': Verified facts about the external author/media.
3. 'content_evidence': Key facts/impressions from the original material.
4. 'channel_context': Recent publications to avoid repetition.

RULES:
1. Select exactly one 'source_angle_id' that best highlights WHY this external view is interesting.
2. Determine 'throughline_mode':
   - Use 'explicit_transition' ONLY if there is a genuine geographic or thematic link to the immediately previous post.
   - Use 'contrast_or_scale_shift' to change pace (e.g., city to nature, macro to micro).
   - Use 'fresh_start' if connecting to history feels forced or if recent openings are repetitive.
3. Define 'why_this_material_now': A one-sentence internal reasoning for what makes this specific material worth clicking.
4. Define 'opening_device': How to start paragraph 1 without using banned lexemes from the context.

Respond in strict adherence to the EditorialPlanOutput schema. Language: Russian for text fields, exact IDs for references.
Prompt 2: Grounded WriterPlaintextYou are the Onboarding Writer for "Region Talk". 
Write EXACTLY two paragraphs in Russian based STRICTLY on the provided 'editorial_plan' and 'evidence'.

RULES:
Paragraph 1 (Source & Bridge):
- Introduce the source based on 'source_angle_id'. 
- Establish their non-regional perspective.
- Implement the 'throughline_mode' and 'opening_device'.
- DO NOT write a standard biography.

Paragraph 2 (Material & Motivation):
- Describe 1-2 specific observations from 'content_evidence' in the THIRD PERSON (e.g., "автор замечает", "исследование показывает").
- NEVER use first-person plural ("мы увидели") for the author's experience.
- Give a clear reason to open the original link. Do NOT summarize everything.
- If 'visual_hook_evidence_ids' is provided, mention the visual value correctly (do not claim rights we don't have).

GROUNDING:
Every factual claim must trace back to an evidence ID. Do not invent professions, cities, or emotions.
Tone: Warm, observational, editorial. No clickbait ("уникальный", "шок"), no sales tone, no PR jargon ("в рамках проекта").

Respond in strict adherence to the WriterOutput schema.

Deterministic ValidatorsРегулярные выражения (Regex) не могут проверить галлюцинации или третье лицо. Детерминированные проверки в пайплайне (на Python/Telethon) должны отсекать технический брак до LLM-Critic.Список детерминированных проверок:Length Check: len(p1) + len(p2) <= 900 chars.Paragraph Count: Ровно один символ \n\n в combined_text.Banned Lexemes (Regex): Отсутствие слов-маркеров AI и кликбейта (уникальный, невероятный, обязательно посмотрите, в данной статье, в рамках).Reference Integrity: Все evidence_ids в grounding_map существуют во входном JSON.Language Check: Символы кириллицы > 95% (за исключением ID и английских терминов, если они есть).7. История и anti-templateАлгоритм выбора:В YDB хранится таблица последних 20 публикаций с их editorial_plan. Перед запуском Planner вытаскивает 3 последние.Если geography предыдущего поста близка к текущему — доступен contrast_or_scale_shift (масштабирование).Если lane поменялся (Social -> Academic) — рекомендуется explicit_transition (смена оптики).Условие для fresh_start: Если в последних 3 текстах 2 раза использовался переход, следующий обязан быть fresh_start.8. Social, Article, Academic, Cafe PolicySocial: Запрет на объективизацию. Все утверждения подаются через призму («автор заметил», «автору показалось»).Article (Проф. медиа/блоги): Фокус на методе (как собирали материал, с кем говорили).Academic: Жесткий блок на overclaim. Запрет слов «доказали», «определяет». Допустимы «обнаружили корреляцию», «в исследуемой выборке».Cafe Policy (Boundary): Жесткий reject, если текст содержит цены, меню, призывы бронировать, слова «вкусно/невкусно» как главный фокус. Pass только если кафе рассматривается как урбанистический или архитектурный объект (ревитализация пространства, антропология).9. Визуальный hook в текстеЕсли rights_policy == "media_reuse_allowed" (или мы генерируем собственные векторные карточки/графику): Писать «Мы собрали ключевые кадры в карточки...» или «Публикуем серию в канале».Если rights_policy == "forward_allowed": Писать «Серию фотографий можно посмотреть в оригинальном посте, который мы переслали ниже».Если rights_policy == "link_only": Строго «Отдельный повод открыть пост — визуальный ряд, где автор показывает...».10. Evaluation rubric и test suiteШкала 0–4 (0 - hard fail, 1 - poor, 2 - acceptable, 3 - good, 4 - exceptional).Hard Fails (мгновенный Reject = 0):Unsupported Claim: Добавлен факт, которого нет во входе.Voice Violation: Использование «мы/наш» для чужого опыта (присвоение).Visual Hallucination: Упоминание фотографий, когда visual_evidence пуст.Cafe Violation: Наличие рекламных призывов или цен.Обработка реакций (Editor Labels):👍 (Ready) -> Отправка. Пополняет базу удачных editorial_plan (RAG для future prompts).✍️ (Rewrite) -> Временный отказ. Оператор дописывает комментарий, уходит на Stage 3.👎 (Reject) -> Пополняет negative constraints (anti-patterns) базы.11.

# Какие сайты добавляют сведения об экскурсиях Калининградской области

Проверка 16 ноября 2026 года. У регионального ТИЦ можно автоматически найти «Рассвет над Балтикой», связать маршрут с Нозой Усмановой и получить описание, которого не было в ноябрьской строке расписания. В афише «Фридландских ворот» можно обнаружить конкретный ноябрьский выезд. Это два разных результата мониторинга. Для первого нужна запись об источнике описания уже известного маршрута, для второго — свидетельство о сеансе с датой и временем. Сколько действительно новых выездов сайты дадут сверх VK и Telegram, покажет сравнение с базой. [Разбор Fable](vk-narrative-fable-verdict-round-2-2026-11-16.md)

## Что действительно отдаёт сайт ТИЦ

Проверены публичные страницы и все 14 дочерних карт сайта обычным HTTP GET из рабочей среды ChatGPT. HTML разбирался без JavaScript, авторизации и языковой модели. Отдельная сетевая проба на хосте DevCoveer `events-bot-new` завершилась `timeout` примерно через 5,2 секунды. Эти измерения описывают разные среды. Доступ из контейнера ежедневного мониторинга или из его Kaggle-запуска этим опытом не подтверждён.

### Что сделал адаптер мониторинга

На изолированной SQLite с четырьмя строками подборки A полный обход 16 ноября прочитал 22 из 22 страниц списка (общий каталог и 21 раздел). В них нашлось 122 различных ссылки. По названиям известных маршрутов потребовалась одна детальная карточка. Заголовок, программа и личность гида совпали только у выезда №746. В поле `route_background` попали URL, время проверки и текст про Ленинский проспект и первых переселенцев. Количество ошибок и отложенных страниц — ноль. Остальные три строки сохранили свои исходные материалы. Проверка подтверждает механизм обогащения одной подборки. Для измерения прироста новых выездов нужен другой подсчёт по календарям, описанный ниже.

## Как включить эти данные в обычную работу

1. **Сбор.** У мониторинга есть свой реестр сайтов с владельцем, стартовыми адресами и назначением — маршрут, расписание, календарь сеансов или справочник гидов. Для ТИЦ начать с карт и их публичных геостраниц. Хранить канонический URL, время получения, даты действия сведений, хеш извлечённого блока и фрагмент, подтверждающий каждое используемое поле. У музейного расписания дата может быть на странице списка, а описание и цена — по другой ссылке. Повторный обход того же снимка должен сохранять прежний результат без дубля.
2. **Актуальность.** Начальный режим — раз в сутки до отбора дайджеста перечитать ближайшие даты и изменившиеся страницы. Справочники гидов и архивные программы можно проверять реже, например раз в неделю, с условным GET при наличии `ETag` или `Last-Modified`. При ошибке загрузки сохранять прошлое наблюдение с его датой. Пустая выдача, снятие с продажи и явная отмена — разные состояния. У архивной программы сохранять маршрут и автора; её цену, остаток мест, точку сбора и расписание нельзя переносить в другой сеанс.
3. **Сопоставление и запись.** Использовать стабильный идентификатор или каноническую ссылку организатора. Для независимых источников сверять автора или организацию, маршрут, город отправления и, при объединении сеансов, местную дату и время. «По запросу», бессрочная выставка и список рабочих часов сами по себе нового выезда не создают. Факт о текущем выезде привязывать к его `ExcursionOccurrence`, постоянную тему — к подтверждённому `ExcursionTemplate` и гиду. Для формата данных использовать действующую границу `GuideProfile / ExcursionTemplate / ExcursionOccurrence / GuideFactClaim`. [Устройство мониторинга](README.md)
4. **Извлечение.** Для календаря и ODS использовать адресные правила и проверять обязательные поля. `gpt-6.1-sol-lite` можно сравнить на трудных описаниях после сохранения страницы. У ответа должна быть цитата из конкретного блока и ссылка на снимок; добывать пропущенное время или выбирать между понедельником и вторником модель не должна. Полезность этой модели относительно правил пока не измерялась. Playwright относится к получению содержимого динамической страницы, Sol — к интерпретации уже полученного текста, основной Sol дайджеста — к написанию по материализованным фактам. Сбой отдельного сайта не должен прерывать остальные источники.

**Что считать результатом пилота.** На одном и том же горизонте и снимке базы сопоставить «VK + Telegram» и «VK + Telegram + сайты». Вывести число уникальных подтверждённых новых сеансов, число уже известных маршрутов, получивших первый проверенный фрагмент описания, дубли и расхождения по датам/ценам, долю страниц с извлечёнными обязательными полями, ошибки и время обхода. Вручную проверить спорные объединения и выборку новых сеансов по URL. Отдельный контроль — №746: описание находится автоматически, ноябрьские дата/время/цена сохраняются; при отсутствии подтверждённой связи текст остаётся кратким. Для «Музейного трамвая» повторный обход той же афиши должен давать единственный сеанс 21 ноября в 12:00. Сезонные графики и поисковые карточки отдельно в число новых подтверждённых сеансов не входят.

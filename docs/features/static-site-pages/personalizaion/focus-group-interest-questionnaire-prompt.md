# Prompt: анкета фокус-группы по интересам для проверки персонализации

> **Статус:** постановка для отдельной проработки анкеты.  
> **Дата среза:** 2026-08-04.  
> **Цель:** собрать self-reported interests и decision-context фокус-группы так, чтобы проверить гипотезы персонализации и golden personas, не подменяя поведенческие сигналы опросом и не собирая лишние чувствительные данные.

## 1. Продуктовое решение

Анкета целесообразна, если она используется как:

1. calibration/evaluation input для ранней модели;
2. источник judgement labels и persona priors;
3. способ проверить, совпадают ли наши гипотезы интересов с реальными людьми;
4. материал для cold-start вопросов;
5. диагностика барьеров: цена, расстояние, время, компания, доверие к событию.

Анкета **не должна** быть:

- обязательным gate к использованию сайта;
- заменой фактического поведения;
- основанием для sensitive profiling;
- способом собрать лишние персональные данные;
- формой «скажите нам всё о себе»;
- причиной автоматического long-term profile без отдельного product/legal flow.

Рекомендуемый формат: 5–7 минут, mobile-first, добровольно, с пропуском вопросов,
без вопросов о политике, религии, здоровье, этничности и других специальных
категориях.

## 2. Как анкета помогает модели

| Что собираем | Как используем |
|---|---|
| Любимые форматы/темы | initial priors и проверка facet taxonomy |
| Контексты посещения | social scenario и constraints |
| Барьеры | typed constraints, не genre dislike |
| Planning style | explanation/copy and ranking nudges |
| Pairwise choices | human preference labels для offline evaluator |
| Последние хорошие/плохие события | qualitative validation, не автоматический profile import |
| Что точно не предлагать | candidate typed negatives для cold-start design |

## 3. Prompt для отдельного окна

Скопировать в отдельный запуск:

```text
Разработай анкету фокус-группы для проверки гипотез персонализации сервиса
«Полюбить Калининград Анонсы».

Контекст:
- Есть статический сайт с будущей персонализацией событий.
- Целевая модель описана в
  `docs/features/static-site-pages/personalizaion/personalization-to-be.md`.
- Нужны данные для проверки golden personas, интересов, контекстов посещения,
  ограничений и cold-start вопросов.
- Анкета должна помогать model calibration и longitudinal E2E, но не должна
  становиться источником чувствительного профилирования.

Главная задача:
Сделай короткую mobile-first анкету на 5–7 минут для фокус-группы, которая
позволит:
1. проверить, какие темы/форматы реально интересны людям;
2. увидеть контексты выбора событий: один, семья, друзья, туристический сценарий;
3. выявить ограничения: цена, расстояние, время, транспорт, компания;
4. проверить гипотезы Golden personas без hard-label навешивания;
5. собрать pairwise/preference labels для offline evaluator;
6. подготовить возможный cold-start опрос для сайта;
7. сформировать данные, которые можно сравнивать с фактическим поведением на
   сайте после серии визитов.

Ограничения:
- Не спрашивать политические взгляды, религию, здоровье, этничность, интимную
  жизнь и другие специальные категории.
- Не спрашивать точный адрес, доход, место работы, паспортные/сильные PII.
- Все вопросы должны быть добровольными и иметь «Пропустить» / «Не хочу отвечать».
- Не обещать, что анкета сразу идеально настроит рекомендации.
- Не делать один persona label итогом анкеты; persona — мягкая смесь + unknown.
- Развести вкусы и ограничения: «дорого», «далеко», «не в это время» не равны
  «не люблю жанр».
- Не перегружать: максимум 15–18 экранов/вопросов, лучше меньше.
- Должна быть понятная редакционная тональность KenigEvents: спокойный культурный
  навигатор, без сухости и без заигрывания.

Нужно вернуть:
1. Цели анкеты и как ответы попадут в модель/оценку.
2. Финальный список вопросов с типом ответа.
3. Какие поля попадут в structured output.
4. Как ответы мапятся на facets/personas/constraints/horizons.
5. Какие вопросы идут в обязательный минимум, какие можно убрать.
6. Какие вопросы лучше не задавать и почему.
7. Текст вступления и завершающего экрана.
8. Схему использования результатов в longitudinal E2E и offline evaluator.
9. Риски bias/privacy и как их снизить.
10. Markdown-версию анкеты и JSON schema ответа.

Сделай результат практичным: чтобы его можно было передать дизайнеру/кодеру и
быстро собрать форму для фокус-группы.
```

## 4. Предварительная структура анкеты

1. Вступление: зачем анкета, добровольность, 5–7 минут.
2. Как обычно выбираете события: заранее/спонтанно/по компании/по погоде.
3. Темы и форматы: multi-select + «другое».
4. Контекст: один/пара/семья/друзья/турист/профессиональный интерес.
5. Ограничения: цена, время, расстояние, транспорт, возраст детей, доступность.
6. Novelty: знакомое / соседнее / необычное.
7. Pairwise choices: 5–7 пар событий или абстрактных сценариев.
8. Что точно не предлагать: typed negative, optional.
9. Последнее событие, которое понравилось: optional free text.
10. Что раздражает в рекомендациях: optional.
11. Завершение: как ответы помогут настроить и проверить модель.

## 5. Как сравнивать с поведением

Для focus-group participants, давших анкету и фактическое поведение:

- self-reported facets vs observed strong actions;
- constraints vs hide reasons;
- pairwise choices vs actual rank/click/save;
- planning style vs save/calendar/CTA timing;
- persona mixture prior vs model-inferred distribution;
- mismatch report: где анкета и поведение расходятся.

Расхождение не всегда ошибка: человек может хотеть одно, а реально выбирать
другое из-за времени, цены, компании или контекста. Отчёт должен разделять
`taste mismatch`, `constraint mismatch`, `supply mismatch`, `UI discovery issue`.

## 6. Decision

Анкету стоит делать как отдельный optional focus-group research artifact. Она
поможет ускорить калибровку, но не закрывает сама по себе качество модели. В
release gates она входит как evaluation/supporting evidence, а не как production
personalization proof.

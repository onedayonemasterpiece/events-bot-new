# Консолидированные требования из Telegram (сообщения 803–850, 29.07.2026)

Эта секция добавлена как traceability-реестр. Авторский сценарий выше не
переписывается; новое замечание меняет только указанную сцену и явно
переоткрывает её согласование.

## Требования к текущей итерации

1. **Стабильный пульт** (`840`, видео `845`): status/detail не должны прыгать
   при polling и смене текста; под них резервируется постоянная геометрия.
2. **Лекция управляется вручную** (`843`): семь лекционных экранов — семь
   отдельных сценариев и кнопок. Экран остаётся видимым, пока говорит спикер;
   автоматическая колода запрещена.
3. **Sticky-таймер** (`844`): сверху пульта всегда видно прошедшее время
   презентации. Для intro задаётся время начала и показывается countdown;
   в самом intro периодически появляется «Начнём через N минут».
4. **Разные композиции лекции** (`846`): горизонтальные изображения
   показываются целиком, смысл/подпись размещаются ниже; допустима отдельная
   подпись изображения. Не использовать один split-шаблон для всех кадров.
5. **Знак «Знание» без плашки** (`847`): светлый знак на тёмном фоне, тёмный
   на светлом.
6. **Контраст и ритм тем** (`848`, `849`): чередовать светлые/тёмные сцены;
   рядом с тёмным демонстрируемым сайтом использовать светлую оболочку.
7. **Место для мысли** (`850`): телефон можно сдвигать в сторону ради крупного
   тезиса. Desktop live-показ двухфазный: сначала отдельный смысловой экран,
   затем сайт во весь экран.
8. **Focus-preview**: новые live-сцены показывают версию
   `preview-20260729-focus-simple-r15-a5cc0256`, а сцена фокус-группы — точный
   invitation URL с `#invite=focus-group-2026-announcements`.
9. **Hero Talk**: intro раскрывает фразу смысловыми фрагментами с cursor у
   активного фрагмента, а не печатает по одной букве; две строки и сильная
   типографика сохраняются.
10. **Быстрые итерации**: принятые сцены замораживаются. В очередной итерации
    тестируются только новые и явно переоткрытые части; полный прогон — один
    раз перед финальным handoff.

## Уже принято и заморожено

- автоматический Windows launcher, общий versioned cache и отсутствие Enter в
  happy path (`813–815`, `819`, `831`);
- один browser/context/page/window; следующий Run, Stop и Reset не закрывают
  окно, Shutdown терминален (`819`, `827`, `831`);
- исправления GetStdHandle, UTF-8 и AbortSignal listeners (`814`, `815`);
- снятый 30-секундный rail timeout (`820`, `827`);
- mobile tap/swipe без mouse cursor, принятые сценарии rail-like, artifact и
  QR-outro — не переделывать без нового адресного замечания.

# Консолидированные уточнения после просмотра 29.07.2026 (тема 803)

Ниже — адресные требования следующей итерации. Они не отменяют авторский текст
выше. Каждая строка переоткрывает только названную сцену; остальные принятые
части не переделываются и проходят один общий regression только перед выдачей.

1. **Intro / Hero Talk:** сохранить смысловые фрагменты, но сделать ритм медленнее,
   живее и human-like: разные паузы на знаках препинания и редкие короткие
   «запинки». Пробелы между словами обязательны.
2. При нулевом countdown показывать ровно две строки: **«Вот-вот» / «начинаем»**.
3. **Лекция:** убрать паразитные рамки, поля и растянутые подложки вокруг
   изображений; каждую из семи сцен проверить в FHD глазами.
4. На лекционных кадрах сначала печатается тезис, затем мягко появляется
   изображение. Готовый кадр не должен мигать до начала печати.
5. На «Видеть главное» текст и логотип «Знание» не пересекаются.
6. Последняя схема занимает примерно правую половину FHD и максимально
   увеличена без кропа; внутренние подписи должны читаться из зала.
7. Для «найти / поделиться / не забыть» используются реальные иконки static-site,
   а не отдельно нарисованный набор.
8. Мобильное меню после тапа держится открытым достаточно долго, чтобы зритель
   увидел бирку, список и выбранный пункт; только затем выполняется переход.
9. **03.3 Артефакт:** после «Выходных» обязательно показать поиск, первый сбор,
   сохранение после reload и открытие коллекции. Если в основной focus-сборке
   feature flag выключен, разрешено проверенное актуальное preview-исключение,
   которое явно фиксируется в техдокументе.
10. **Медальоны:** использовать 16 узнаваемых реальных медальонов. Каждый сначала
    показывается крупно, затем становится в сетку 4×4 с небольшим интервалом.
11. **03.7 Шутка:** первая фраза печатается, затем пауза 7 секунд; одновременно
    с печатью второй фразы «нет, мой электронный мозг не создан для шуток…»
    воспроизводится файл из сообщения 856. Служебные слова про паузу не выводить.
12. На презентационных фонах нужен спокойный живой halo, не мешающий тексту.
13. **Умный поиск:** запрос с пульта обязательно отправляется и завершается
    реальными карточками результатов. Для этого используется отдельный
    непривилегированный demo-account и сохраняемая между debug ZIP сессия;
    пароль и token не помещаются в Git/ZIP/логи.
14. Для «презентация пошла не по плану» воспроизводится короткая легально
    используемая error-перебивка. Повторяемый sourcing оформляется проектным skill.
15. Все live-сцены используют актуальную focus-сборку
    `preview-20260729-focus-simple-r15-a5cc0256`; исключение допустимо только для
    выключенного в ней артефакта и должно быть явно названо.
16. **Фокус-группа:** показать крупный QR точного onboarding URL с invite fragment,
    пригодный для сканирования зрителями.
17. **Оценка страницы:** показать реальную календарную страницу, естественно
    прокрутить к существующему блоку «Помогла ли вам эта страница?» 0–10 и
    называть его оценкой страницы, а не выдуманным NPS.
18. **Люди:** использовать проверенные данные Татьяны Удовенко, Андрея Бойко и
    Светланы Соколовой. После презентационного кадра перейти к реальному UI
    участников события/лаборатории и наглядно поставить лайк. До публикации
    participant relations это честно маркируется как preview UI, а не prod-event.
19. **04.1 Завтра:** восстановить сценарий на текущих меню/селекторы и дождаться
    реальной страницы/описания события.
20. **04.2 Rail-like:** использовать актуальное событие и снова показать rail до
    правого края, дополнительную протяжку и сохранённый лайк.
21. **04.3 Weekend FHD:** показывать актуальные выходные 1–2 августа 2026 из
    текущей focus-сборки и естественно прокрутить desktop-страницу вниз.
22. На пульте справа от сценариев есть вертикальная полоса ручной прокрутки
    экрана вверх/вниз; она не останавливает и не закрывает текущую сцену.
23. Пульт остаётся PWA «Пульт презентации» с коротким именем «Пульт»; отдельная
    подтверждаемая команда «Закрыть презентацию» остаётся терминальной.
24. Windows launcher продолжает полностью автоматически переиспользовать общий
    cache Node/Playwright/browser; там же хранится browser state demo-search.
25. Разработка идёт короткими адресными итерациями: targeted tests для
    переоткрытых сцен, FHD visual review изменённых лекционных кадров и один
    полный regression/Windows smoke непосредственно перед handoff.

# Дополнение после просмотра текущей сборки 29.07.2026 (итерация C)

Эти пункты адресно переоткрывают только названные сцены. Остальные принятые
части не переделываются до финального regression.

1. Все обычные live-вставки используют focus-build
   `preview-20260729-focus-simple-r15-a5cc0256`; предоставленная страница
   `sobytiya/triatlon-pokoleniy-kaliningrad-6865/` обязательна для актуального
   мобильного примера. Desktop-пример медальонов может использовать другую
   страницу **той же сборки**, если только она содержит требуемые top-slot,
   горизонтальный hero и минимум два inline-медальона.
2. Вход изображений и QR использует заметную кинематическую ease-in-out
   траекторию с движением и коротким settle, а не один медленный fade.
3. Презентационная сцена использует локально поставляемый Cygre; синтетические
   веса 900+ запрещены. Заголовки должны читаться из зала и иметь ясную
   иерархию.
4. Human-like typing немного ускоряется, паузы детерминированно варьируются по
   буквам, границам слов и пунктуации; одинаковый периодический ритм запрещён.
5. В 03.2 используются точные static-site glyphs: search, event share и
   calendar без CSS, ломающего их fill/stroke.
6. 03.3 обязательно показывает зрителю хотя бы один реальный горизонтальный
   сдвиг rail, удерживает найденный артефакт, явно сообщает стадии долгой
   операции и завершает reload/коллекцией.
7. В 03.4 слово «Медальон/Медальоны» видно в заголовке. Каждый образ появляется
   по центру области сетки и тем же объектом уменьшается/перемещается в свою
   ячейку 4×4; тяжёлая белая окантовка запрещена.
8. В 03.8 «Умный поиск» — главный крупный заголовок; принцип поиска по смыслу —
   второй уровень иерархии.
9. 03.9 успешен только после реального submit и карточек выдачи. До однократной
   подготовки отдельной непривилегированной Windows demo-сессии сцена обязана
   показать честную ошибку, не имитируя поиск.
10. 03.10 воспроизводит слышимую легально используемую Windows-style
    error-перебивку; playback проверяется по реальному продвижению audio.
11. В 03.13 главным сообщением является «Присоединяйтесь к фокус-группе»;
    текст и QR не пересекаются в FHD.
12. В 04.2 rail до края, дополнительная протяжка, поставленный лайк и его
    сохранение после reload имеют видимые выдержки для аудитории.
13. Круговые декоративные кольца презентационных кадров заменяются точной
    растянутой буквой «о», выделенной из фирменного SVG «Анонсы».
14. Название PWA: полное «Пульт презентации», короткое «Пульт». Сцену 03.14
    называть «Оценка страницы», не NPS. Preview UI людей явно маркируется как
    ещё не опубликованная связь с production-событием.

# Технический сценарий показа 30 июля 2026

Статус: `working_owner_test_candidate`.

Исходные авторские требования неизменно хранятся в
[`scenario-30072026-base.md`](scenario-30072026-base.md). Этот файл фиксирует
реализованные сцены, runtime-контракт и подготовленные медиа. Реализация
намеренно явная: без универсального DSL, редактора и очереди.

## Среда показа

- один Windows agent создаёт один browser, один BrowserContext и одно
  fullscreen-окно 1920×1080 на всю сессию;
- следующий Run кооперативно останавливает текущую сцену и меняет содержимое
  того же stage; Stop и Reset окно не закрывают;
- только подтверждённая команда «Закрыть презентацию» завершает browser,
  agent и launcher;
- длинные сцены остаются прерываемыми: `intro-loop` имеет явный предел 60 минут
  и штатную длительность 50 минут, live-site сцены — 120 секунд, лекция —
  180 секунд, а загруженное QR-аутро — 30 секунд;
- runtime-медиа выдаются immutable content-addressed URL через уже существующий
  `static.kenigevents.ru`; новые bucket, CDN и Fly-приложения не создавались.

## Реализованные сцены

### `intro-loop` — интро перед началом

Длительность по умолчанию — 50 минут. Полноэкранная тёмная композиция выводит
двухстрочные мысли сильной типографикой и мягкой печатью по графемам:

1. «Добро пожаловать! / Скоро начинаем.»
2. «Почему одни сервисы удобны, / а другие — нет?»
3. «Знакомьтесь друг с другом. / Сегодня здесь особенные гости.»
4. «Сегодня жарко. / Спасибо, что вы с нами.»
5. «Сначала — короткая лекция. / Потом вы — фокус-группа „Анонсов“.»

Порядок выбирается из четырёх заранее логичных маршрутов; приветствие остаётся
первым, а тема и формат не разрываются случайной перестановкой. На экране
постоянно виден знак «Знание». Фоновый `Echo Sax End` плавно входит на громкости
0.15. Переключение сцены немедленно останавливает таймеры и звук.

### `lecture-deck` — лекционный блок

Семь полноэкранных слайдов автоматически сменяются каждые 8,5 секунды. Каждый
кадр содержит знак «Знание», один крупный тезис и исходное изображение из
Telegram-сообщения владельца:

| № / message | Тезис |
|---|---|
| 01 / 821 | Интерфейс видят. Опыт проживают. |
| 02 / 822 | Удобство проверяется действием. |
| 03 / 823 | Интерфейс должен быть под рукой. |
| 04 / 824 | Когда всё важно — ничего не понятно. |
| 05 / 825 | В сложных системах удобство — безопасность. |
| 06 / 826 | Хорошая система помогает видеть главное. |
| 07 / 830 | Понять → спроектировать → проверить. |

Изображение входит мягким `transform + opacity`; aspect ratio сохраняется,
портретный кадр получает отдельную подложку. `prefers-reduced-motion` убирает
декоративную анимацию, не скрывая содержание.

### `weekend-desktop` — desktop «Выходные»

Stage без подписей и бокового интерфейса занимает ровно весь FHD viewport и
загружает настоящую страницу `/vyhodnye/` в desktop iframe 1920×1080. После
готовности `[data-date-listing="weekend"]` Playwright выполняет видимую
естественную wheel-прокрутку сверху до footer. Поскольку эта сцена не нажимает клавиши, desktop key-overlay не
показывается. Это узкий owner-test контракт,
а не универсальный desktop renderer.

### Существующие сцены

- `tomorrow-mobile` — «Завтра», rail и описание события;
- `tomorrow-rail-like` — rail-жест до штатного сохранённого лайка;
- `weekend-amber-artifact` — поиск и открытие янтарного артефакта;
- `outro-qr` — полноэкранное «Как вам?» и QR опроса.

Все семь сцен выбираются из PWA «Пульт презентации» и работают в одной
непрерывной presentation session.

## Визуальный и acceptance-контракт

- одна короткая мысль читается из зала; служебные статусы и селекторы не видны;
- intro, lecture, mobile, desktop и outro переключаются без пересоздания окна;
- desktop iframe имеет bounding box `0,0,1920,1080`; рядом нет надписей;
- CDN-медиа должны загрузиться до выполнения сцены;
- Stop/Reset нетерминальны, Shutdown терминален;
- owner-test остаётся `NOT_M3`: target Windows 10 compatibility evidence и
  публичная репетиция всё ещё обязательны.

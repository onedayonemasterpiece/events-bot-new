> 6 сентября 2026. Задача для прямого запуска в Codex/кодовой среде, не для нового исследовательского окна ChatGPT и не для запуска ещё одного оркестратора.

## 1. Поручение и результат

Доведи **главную `/`** «Полюбить Калининград Анонсы» до собранной, работающей и визуально нормализованной страницы, которую владелец может открыть на desktop/телефоне и начать аудиоревью. Не заканчивай инвентаризацией, реестром, тестами без страницы или ещё одним предложением реализации.

Выполни source changes, исполняемый UI SoT, проверки, GitHub commits и один проверенный immutable preview по существующему пути. Нормализованная главная должна использовать общие карточки, сетку, типографику, иконки и действия сайта — не локальный визуальный fork. Сохрани уже работающие наработки.

### Последняя коррекция владельца — приоритет над предыдущими пересказами

На главной **только нижний плавающий остров**, на desktop и mobile в адаптивной форме общего компонента. Содержимое страницы идёт в таком порядке:

```text
Hero-talk
→ голосовой/текстовый набор запроса
→ быстрые ссылки
→ карточки-лента
→ Hero-talk-page-end
```

Голосовой набор на главной — вход в поиск. После завершения/отправки запроса происходит переход на `/poisk/` с его сохранением. Ответы, история, поиск по каталогу и уточнения находятся на странице поиска, не в главной.

Не добавляй верхний остров, полку городов, липкие быстрые ссылки, плавающий заголовок, второй voice dock/composer или чат под hero. Обычный бренд и нужные служебные элементы общей оболочки можно сохранить **в потоке**: запрещён именно лишний постоянный floating chrome, а не доступ к аккаунту или accessibility. Auth/permission/system dialogs не объявляются вторым навигационным островом, но не превращаются в постоянную панель.

Это route-specific решение для home, а не отмена Floating Islands на календарных страницах/подборках/поиске. Не меняй геометрию выходных и не начинай нормализацию всех архетипов заново.

## 4. Работа по блокам

### A. Единственный нижний остров

Применить общий нижний четырёхпунктовый компонент (`afisha`, `dates`, `search`, `personal`) на обоих классах устройств; на home активна афиша. Имена, иконки, назначение и accessibility брать из текущего общего shell.

Завести/использовать явную home composition policy в существующем shell/SoT, чтобы верхние floating participants **не монтировались и не запускали listeners**. Недостаточно скрыть их CSS поверх продолжающего работать контроллера. Проверить уже существующий `data-floating-context-label` у Hero-talk: на home он не должен порождать верхний остров.

Нижний остров не перекрывает последние карточки, page-end CTA, focus, сообщения и экранную клавиатуру. Его видимость при открытой клавиатуре и порядок transient surfaces принадлежат общему shell, без home-only второго z-index менеджера. Нет морфинга H1/быстрых ссылок в верхнюю панель при scroll.

### B. Hero-talk

Доработать существующую family v2, сохранив typed semantic fragments, мозаику одной настоящей фотографии, конечные состояния и стабильные ссылки. Материальное изменение зарегистрированного контракта требует явной следующей версии/миграции по DS, а не silent mutation.

Проверить факты, название/CTA/media на одном объекте; отсутствие фото даёт text-only, пустой/устаревший event deck — полезный generic service scene, не исчезновение всей вступительной области. Не выводить `feed[0]` как автоматическое доказательство ключевого события. Не увеличивать высоту hero так, чтобы искать/выбирать приходилось через несколько экранов.

Есть реальный действующий campaign resolver/manifest — подключить его eligibility, lifecycle, disclosure и caps. Нет готового автонаполнения — использовать текущие проверяемые редакционные/каталоговые сцены, минимальный общий content interface и безопасный fallback. Не выдавать ручной fixture за живую кампанию и не строить новый LLM pipeline. Независимая исследовательская #642 не блокирует сборку renderer и страницы.

### C. Набор → страница поиска

Сделать компактный inline entry **следующим блоком после Hero-talk**: текст, микрофон, понятные состояния набора/сохранения/ошибки. Не floating composer. Текст не заменяет голос, а позволяет исправить или ввести запрос без микрофона.

Поведение:

```text
пользователь явно начинает запись/ввод
→ завершает/отправляет непустой запрос
→ безопасно сохраняется одноразовая передача
→ переход на withBase('/poisk/')
→ существующий Search подхватывает тот же запрос один раз
→ обработка/результаты/уточнения уже на странице поиска
```

Нельзя переходить просто по focus/первому символу или только потому, что нажат микрофон; запись должна реально начинаться с главной. Не жди полного поискового ответа на home. Пустота/тишина/«Отмена» не запускают поиск. Начало новой поисковой задачи не должно незаметно дописываться к чужой/старой беседе; используй явную новую task identity существующего Search.

Переиспользуй capture/recovery/transcription ownership #587. Если текущий вход отдаёт transcript — передаётся он; если source-first pipeline обрабатывает audio на Search — передаётся сохранённый utterance/ref. Это не требует второго ASR или потери голосового сценария. Для внешнего вида выдели presentation axis/тонкий адаптер существующего ядра, а не скопированный 1000-строчный виджет.

**Надёжность перехода — обязательная часть задачи:**

- до document navigation дождаться finalization/flush и подтверждённого сохранения payload в существующем owner-scoped store; закрыть capture и отпустить микрофон;
- receiver после route startup принимает запись с identity, версией и свежестью; повтор mount, reload, Back/Forward, Auth callback и сеть с потерянным ACK не создают второй логический запрос/повторный provider dispatch;
- использовать общий idempotency/receipt lifecycle. Простое «удалить ключ до отправки» теряет запрос при сбое, «прочитать снова при mount» дублирует его;
- не класть raw voice/transcript, токены или профиль в URL/логи; URL может нести только безопасную ссылку на локальную передачу, если она действительно нужна. Существующие публичные search URL не ломать;
- сохранить base-prefix, same-origin/preview isolation, owner isolation и logout/reset boundaries. Не передавать Blob URL как долговечное хранилище;
- eligibility/Auth и privacy сохраняются: login сам не является submit. Незавершённый draft после входа требует явного продолжения; ранее явно отправленный запрос восстанавливается по общему contract, без повторного эффекта;
- storage failure/denied mic/offline/недоступный backend: не уходить, потеряв запись. Понятное восстановление или текстовый путь. `capture-only` тест не выдаётся за voice→search acceptance.

Если реальная shared Search dependency недоступна, выполни все независимые блоки и интеграционные тесты на fixtures, укажи точный внешний blocker и не объявляй рабочий голос по mock. Самодельным Web Speech/новым провайдером этот gap не обходить.

### D. Быстрые ссылки

Сегодня, Завтра, Выходные, Бесплатно, Выставки, Необычное — обычные компактные ссылки общего DS, после поля ввода. Вся группа **в потоке**, без sticky/города/счётчиков/дополнительной витрины. Используй реальные доступные routes и `withBase`; недоступную feature не рекламировать. Если явный географический контекст уже задан в общем состоянии, корректно сохрани его при переходе без новой полки городов на главной.

### E. Карточки-лента

Сохранить существующие AdaptiveEventCardGrid/EventCard/MediaFrame и recent framing corrections. Три обычные колонки на широком desktop, одна на mobile; остаток ряда не растягивается на всю ширину. SSR и hydrated cards используют те же owners, данные и действия. Не возвращать image fields, произвольные обрезки, неодинаковые ширины карточек в ряду или удаление допустимых событий ради раскладки.

Нормализовать заголовок/расстояния/фон/реакции/CTA по **тем же ролям**, что на принятых реальных подборках. Удалить технический текст «Локальных оценок N» из пользовательского интерфейса. Название состояния персонализации должно быть правдивым; общая подборка не подписывается персональной.

Цель до 30 карточек — про качество выбора повторного пользователя, не только `limit`. Подключить готовый shared profile/ranking path, не новый recommender. Проверить кандидат за пределами popularity top-30; сохранить ограничения, family identity, exact hide/Undo, возврат со scroll position и неподвижный видимый префикс. Если общий materializer не готов, явно разделить нормализацию UI и недоказанный personalization outcome.

Не навязывать придуманные в предыдущем draft порции `12+9+9` и не создавать свою pagination ради них. Сохранять текущий конечный home budget и общую механику раскрытия/загрузки, если они совместимы с новой композицией. `30` не ограничивает каталог/поиск. Hero/family дубли устраняются по общим IDs; не вычитать места из показанного списка при каждом animation frame и не переставлять видимые карточки из-за новой сцены.

### F. Hero-talk-page-end

Добавить настоящий нижний placement **после ленты**. Общая семантика Hero-talk, отдельная компактная композиция: контекстная фраза и один основной следующий шаг, без второго hero большого размера/ленты related. Не переименовать старый onboarding slot и засчитать его как Hero-talk без реализации нужного контракта.

Основной home сценарий — помочь уточнить выбор через `/poisk/`. Не говорить «Ничего не нашли?» как установленный факт. Уважать уже выполненное действие, hide, capability readiness и suppression/campaign caps. Не повторять уже показанное верхнее промо. Если следующего полезного действия нет — допустимо отсутствие блока.

Реализовать/расширить общий placement/API так, чтобы его могли использовать event/listing/collection/search. **Массовое подключение и redesign остальных страниц — не эта задача.** На уже существующих consumers только необходимые migration/regression checks; расширение future consumers остаётся отдельной доставкой. #642 владеет автоматической актуальностью наполнения, не геометрией страницы.

## 5. Нормализация = runtime + исполняемый SoT в одной доставке

Обновляй реально используемые family/version registry, resource/asset bindings, responsive states, page composition и interaction semantics. `home lower-only` должно быть в машиночитаемой page policy, а не только в Markdown/тестовом CSS. Синхронизируй соответствующее home исключение в действующих DS composition docs; не меняй глобальную policy других архетипов.

В каждом coherent changeset: Astro/общие consumers + исполняемый SoT + нужные tests/catalog docs + CHANGELOG. Между репозиториями — связанные commits/PR и точная пара SHA, не обещание «SoT потом». Один владелец геометрии/токенов/иконок на роль. Не заменять нормализацию переименованием сохранённых разных цветов в разные токены.

Новый внешний вид не канонизируется просто потому, что скриншот снят: сравни одинаковые роли с текущим продуктовым baseline, проверь реальные вычисленные стили, факты, клики и media treatment. Лаборатория может быть техническим свидетельством, но не заменяет нормальную пользовательскую `/`.

### Реальный корпус и Penpot

Подготовь home-specific replay fixture из **реального разрешённого корпуса** текущего preview: source snapshot/hash, замороженные часы Europe/Kaliningrad, exact event/family IDs/order, тексты, asset hashes, допустимые профили/сцены/кампании и состояния. Не используй корпус «Бесплатно» как доказательство всех состояний home и не выдумывай production data. Синтетические corruption/adversarial cases — отдельные test fixtures.

Одни и те же данные подставляются в локальный focused Astro diagnostic, общий опубликованный build и SoT projection. Для Hero-talk зафиксируй воспроизводимые состояния text-only/photo/terminal; анимацию проверяй отдельно. Проверить не только первый экран, но низ страницы, часть ряда, раскрытие и post-hydration.

Следуй **текущему review stage**, не старому main contract: на подготовленном срезе conformance1.2.0 допускает owner audio review при проверенной source-bound structural projection без полной native materialization страницы. Поэтому:

- обязательны исполняемый SoT и validated export readiness home, не пустой inventory/null bindings;
- full native P не блокирует независимую Astro/source/preview работу;
- без реального round-trip запрещено заявлять `A=S=P`;
- существующие обязательные native catalog bindings затронутых иконок/overlays не вычёркиваются, но не превращаются в повторное построение всего каталога;
- при доступной разрешённой материализации — использовать current existing file/sole writer, readback revision и native linked components; не создавать второй файл и не выдавать screenshot-подложку за компоненты. Исторический file ID не является fresh authority.

## 6. Минимальная доказательная приёмка

Проверки выполняй против actual implementation, а не source regex вместо поведения.

| Сценарий | Что должно быть доказано |
|---|---|
| Структура 1440×900 / 1920×1080 / 390×844, дополнительно narrow360 | Правильный порядок пяти блоков; один нижний остров; нет верхних participants до/после scroll, лишнего чата и перекрытия CTA. |
| Hero populated/text-only/empty/stale/reduced-motion | Полезная первая сцена, согласованные факты/CTA/фото, неподвижная доступная ссылка, finite state, без пустого hero. |
| Текст home→Search | Реальный переход с непустым запросом; одна новая задача, один логический submit; результаты только на Search. |
| Голос home→Search | Реальный start capture на home, flush/save/stop, переход, сохранённый payload принят Search, результат; мок и live отдельно. |
| Capture error/тишина/отмена/denied mic/storage failure | Нулевой ненамеренный submit, сохранность возможного draft/audio, ясный recovery. |
| Double submit/refresh/Back-Forward/Auth retry/старый prefix | Нет повторного эффекта и повторной записи при возврате, нет потери данных/чужого owner, корректные links. |
| Лента SSR/hydrated/partial row/feedback/Back | Общие grid/card/media/action owners, все допущенные IDs сохранены, нет неожиданного растяжения/дубля/видимого reorder. |
| Personal/general/empty | Честная подпись режима; constraints/hide/Undo; кандидат вне первоначальных популярных; не выдавать test profile за готовую personalization. |
| Page-end + длинная страница/клавиатура | Находится после содержимого, CTA доступен, dock его не закрывает, верхнее промо не повторено. |
| Быстрые ссылки | Реальные целевые страницы и корректный base-prefix, focus/Enter/touch/no-JS. |
| Shared-shell regression | Поиск/обычная дата/Бесплатно/Weekend не потеряли свои controllers и навигацию; Weekend без redesign. |
| Normalization/SoT | Согласованные роли, состояния, assets/geometry/source refs; нет home-only альтернатив карточек/иконок/шрифтов. |

Запусти применимые текущие scripts из `site/package.json`: DS/family/production-consumer checks, targeted unit/integration tests, preview check и Playwright. Найди актуальные команды, не придумывай PASS. Shared Search tests не заменяют home→Search cross-document test. Микрофон на физическом телефоне/ASR считаются live только при реально доступном устройстве/разрешённом endpoint; не расширять provider budget и не менять flags ради отчёта.

Опубликованный preview — **единственный существующий Kaggle CPU → current bucket → immutable prefix путь**, управляемый доступным установленным фасадом из #621. Local focused diagnostic допустим, но не публикуется обходным загрузчиком и не засчитывается за owner build. Используй существующий page-class filter только если он включает home и все необходимые цели Search/переходов; не вводи второй генератор. Production/root/ICS и live campaign/provider policies без отдельного разрешения не менять.

После публикации лично проверь точный URL и manifest/source SHA, браузерные сценарии, screenshots desktop/mobile/низа и доступность ассетов. Независимый REVIEW verdict используй, когда он реально получен; собственную проверку не называть независимой.

## 7. Завершение и handoff владельцу

Один содержательный итог в #641/#621: что изменено по пяти блокам и нижнему острову, ссылки на code/SoT commits, точный preview/manifest, снимки до/после на одном корпусе, выполненные tests и оставшиеся ограничения. Нужен прямой URL главной, не только служебный preview hub. Не коммить secret bearer links: передавай их через предусмотренный приватный канал, публичные comments содержат безопасную identity.

Формулировка результата различает:

- **Главная собрана и нормализована, доступна для аудиоревью** — только когда все применимые page/runtime/SoT/preview проверки прошли;
- голос live / fixture-only / blocked — отдельно, без объявления рабочим capture-only;
- качество персонального выбора до30 — проверено или ещё не доказано;
- автоматическое наполнение #642 — отдельный проект, не скрытый долг renderer;
- Penpot structural-ready / native-verified — раздельно, без ложного A=S=P.

Если внешний blocker реален, закончи весь независимый scope, сохрани код и проверяемый preview, укажи точный недоступный шаг. Не расширяй эту задачу до ремонта всех внешних подсистем и не останавливайся после первого готового блока. После готовой review-сборки остановись для владельца, без самостоятельного production promotion или нового редизайна.

## Технические справки для handoff (не замена существующего ядра)

Проверенные официальные браузерные описания: MediaRecorder отдаёт final `dataavailable` перед `stop`; IndexedDB transaction `complete` означает успешное завершение транзакции; освобождение захвата выполняется через tracks.stop. Если текущий AudioWorklet имеет другой flush protocol, используй его эквивалентную фактическую гарантию, не переписывай capture на MediaRecorder ради примера.

- https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/stop_event
- https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/complete_event
- https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/stop

Source inspection при подготовке не являлся browser/live/ASR тестом. Автор задачи не запускал кодового агента или сборку.

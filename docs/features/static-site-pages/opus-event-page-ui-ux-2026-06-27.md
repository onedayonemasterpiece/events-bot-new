## 1. Концепция и задача пользователя (5–10 секунд)

### Сценарий входа

Пользователь попадает на страницу одним из трёх путей:

| Путь | Доля (оценка) | Контекст |
|---|---|---|
| Поиск (Яндекс/Google/LLM-сниппет) | 45% | Знает название или ищет «концерт Светлогорск июль» |
| Переход из ленты/агрегатора/Telegram | 35% | Видел анонс, хочет детали и билеты |
| Внутренняя навигация kenigevents.ru | 20% | Листает афишу, кликнул карточку |

### Задача в первые 5 секунд

Пользователь должен без скролла ответить на четыре вопроса:

1. **Что** — название + тип (концерт)
2. **Когда** — дата и время в человеко-читаемом формате
3. **Где** — площадка + город (не путать Светлогорск с Калининградом)
4. **Сколько / как попасть** — CTA «Купить билет» или «Вход свободный»

### Вторичные задачи (10–30 секунд)

- Прочитать описание программы, увидеть фото
- Добавить в календарь / поделиться ссылкой
- Узнать про организатора и источник
- Посмотреть похожие события

### Принцип «No Dead End»

Каждый экран заканчивается действием: либо CTA билета, либо переход к другому событию, либо возврат в афишу. Страница не должна оставлять пользователя без следующего шага.

## 4. Визуальная система

### 4.1. Стиль

Направление: **«Балтийский минимализм»** — чистый, с воздухом, без визуального шума. Атмосфера побережья: приглушённые тона, акцент на контенте. Никакого клишированного градиента «закат над морем» — вместо этого тонкая текстурность и продуманные тени.

## 5. CTA / Interaction Contract

### 5.1. Карта действий

| # | Действие | Элемент | Поведение без JS | Поведение с JS | Приоритет |
|---|---|---|---|---|---|
| 1 | Купить билет | `<a>` primary button | Переход на `ticket_link` | Переход на `ticket_link` (+ analytics) | P0 |
| 2 | Добавить в календарь | `<a href="...ics">` | Скачивание .ics файла | Web Share API -> calendar intent (fallback: .ics) | P0 |
| 3 | Поделиться | `<a href="...">` fallback | mailto: / whatsapp: / telegram: links | `navigator.share()` (mobile), dropdown menu (desktop) | P1 |
| 4 | Копировать ссылку | `<a>` с `data-copy` | Не отображается (`<noscript>` скрыт) | `navigator.clipboard.writeText()` + toast «Скопировано» | P1 |
| 5 | Открыть на карте | `<a>` geo-link | `https://yandex.ru/maps/?text=...` | Тот же URL | P2 |
| 6 | Источник/Telegraph | `<a>` external | Переход по URL | Переход + `rel="noopener ugc"` | P2 |

### 5.2. Sticky CTA (mobile)

- Появляется когда hero-блок с основной CTA уходит за viewport (IntersectionObserver).
- Без JS: не отображается (graceful degradation — основная CTA всё равно в начале страницы).
- Высота: 64px, `backdrop-filter: blur(12px)`, полупрозрачный фон.
- Содержит: название (truncated) + кнопку «Купить билет».

### 5.3. Ticket Link Trust

`ticket_trust_level: "high"` — кнопка без предупреждений. Для `trust_level: "low"` или `null` — показывать caption «Ссылка ведёт на внешний сайт, проверьте надёжность продавца».

### 5.4. .ics Generation

Файл генерируется server-side, URL: `/sobytiya/pesni-sssr/event.ics`

## 6. Related Events / Personalization / Anti-Bubble / Promo

### 6.1. Секция «Похожие события»

**Логика отбора (server-side, при генерации страницы):**

1. Та же площадка + ближайшие даты (приоритет)
2. Тот же `event_type` + тот же город
3. Тот же фестиваль
4. Заполнение до 3–5 карточек

**Freshness gate:** события с `date < now()` не включаются. Если `lifecycle_status != "active"` — не включаются.

Для данного события «Песни СССР» (2026-07-11), при snapshot 2026-06-27:

| Слот | Событие | Причина попадания |
|---|---|---|
| 1 | Вадим Самойлов: Агата Кристи с оркестром (27.06) | Та же площадка + концерт |
| 2 | Моя Мишель (08.08) | Та же площадка + концерт |
| 3 | ЛЮБОВНИЧКИ 2 (30.06) | Та же площадка, другой жанр |

«Симфоническая пятница» (26.06) — дата в прошлом относительно snapshot? Нет, snapshot 27.06 00:00 UTC, событие 26.06 19:00 local (UTC+2). К моменту просмотра страницы (27.06) событие завершено — **не включаем** (freshness gate).

«Экскурсия В потоке времени» (26.06, 15:00) — аналогично завершено — **не включаем**.

### 6.2. Секция «Другие жанры рядом» (Anti-Bubble)

Цель: пользователь, ищущий концерты, видит также экскурсии, лекции, выставки в том же регионе. Это сознательный выход из «пузыря» одного жанра.

**Логика:**

1. Исключить `event_type` основного события
2. Тот же город или соседний (Светлогорск/Калининград — один регион)
3. Ближайшие по дате, `lifecycle_status: "active"`, дата >= now()
4. 2–3 карточки

**Визуальное отличие:** другой заголовок секции, caption «Не только концерты — в Светлогорске и рядом».

### 6.3. Client-side Personalization (optional, после загрузки)

```
GET /api/v1/related?event_id=5878&city=svetlogorsk&exclude=3000,4040,5495&limit=3
```

- Загружается **после** DOMContentLoaded, не блокирует рендер
- Использует `localStorage` для анонимных предпочтений (просмотренные event_type)
- Ответ **дополняет**, а не заменяет server-rendered блок
- Если fetch fails — ничего не ломается, server-rendered блок остаётся

### 6.4. Promo Placement

**Слот #1: между Source и Related** (mobile) / **в sidebar под fact block** (desktop)

Требования:

| Аспект | Правило |
|---|---|
| Разметка | `<aside role="complementary" aria-label="Партнёр">`, класс `.promo-slot` |
| Метка | Текстовая метка «Партнёр» или «Реклама» — всегда видна |
| Стиль | Тонкий левый бордюр `--color-promo`, без агрессивной анимации |
| Содержимое | Статический HTML, без стороннего JS в hot path |
| Fallback | Если нет рекламодателя — блок не рендерится (не пустое место) |
| Не показывать | Промо с `event_type` того же события (каннибализация) |

**Слот #2 (опциональный): между Anti-Bubble и FAQ** — только если есть второй рекламодатель. Не более 2 промо-слотов на страницу.

- Не отправлять: scroll depth, mouse movement, resize, focus/blur.

## 10. P0 Acceptance Gates и Риски

### 10.1. P0 Acceptance Gates

Каждый gate должен быть пройден перед релизом:

| # | Gate | Критерий | Как проверить |
|---|---|---|---|
| 1 | No-JS rendering | Все 4 вопроса (что/когда/где/CTA) видны без JS | Disable JS in browser, визуальная проверка |
| 2 | Mobile CTA above fold | Primary CTA видна без скролла на 375px viewport | Chrome DevTools, iPhone SE |
| 3 | Ticket link works | `ticket_link` корректно открывает страницу билета | Ручной клик, HTTP 200 check |
| 4 | .ics download | Файл скачивается и открывается в Google/Apple Calendar | Ручная проверка на iOS + Android |
| 5 | JSON-LD valid | Google Rich Results Test проходит без ошибок | https://search.google.com/test/rich-results |
| 6 | OG tags render | Preview в Telegram/VK/WhatsApp показывает image + title | https://t.me/iv?url=... , VK debugger |
| 7 | Freshness gate | Прошедшие события не появляются в Related | Тест с `date < now()` |
| 8 | Breadcrumbs | Каждый уровень breadcrumb ведёт на рабочую страницу | Ручной клик по каждому |
| 9 | Performance | LCP < 2.5s на 3G throttled | Lighthouse mobile |
| 10 | Accessibility | Навигация табом по всем CTA, screen reader reads h1+time+location | axe DevTools scan |
| 11 | Canonical URL | Единственный canonical, без дублей, trailing slash | Инспекция `<head>` |
| 12 | Anti-bubble section | Показывает события другого жанра, не дублирует Related | Визуальная проверка |

### 10.2. Риски

| # | Риск | Вероятность | Импакт | Митигация |
|---|---|---|---|---|
| R1 | `ticket_link` содержит пробелы/спецсимволы (как в текущем snapshot: `pesni-sssr%2011%2007`) | Высокая | P0 — пользователь не может купить | Server-side валидация URL, fallback на `source_post_url` |
| R2 | Фото с `userapi.com` — hotlink, может протухнуть | Высокая | Средний — сломанные картинки | Проксирование через собственное хранилище; `onerror` fallback на placeholder |
| R3 | `ticket_status` не обновляется — показываем «В продаже» для sold-out | Средняя | P0 — обманутые ожидания | Пометка «Статус мог измениться, уточняйте на сайте площадки» для не-high trust |
| R4 | FAQ содержит жёстко зашитые ответы, которые могут устареть | Средняя | Низкий | Шаблонизировать FAQ по venue_id, обновлять при изменении данных площадки |
| R5 | Sticky CTA перекрывает контент на маленьких экранах | Средняя | Средний | `padding-bottom: 80px` на `<main>`, z-index management |
| R6 | Прошедшее событие остаётся в индексе, пользователь приходит на мёртвую страницу | Высокая | Средний | Показывать banner «Событие завершено» + перенаправлять в Related; `eventStatus: EventCancelled/EventPostponed` в JSON-LD |
| R7 | Emoji в title события (как `id:6326`) рендерятся некорректно в OG/title | Низкая | Низкий | Strip emoji из `<title>` и OG, оставить в `<h1>` |
| R8 | Desktop sidebar sticky конфликтует с footer | Низкая | Низкий | CSS `position: sticky` + `bottom` boundary на footer sentinel |

### 10.3. Post-Event Lifecycle

Когда `date < now()` и событие завершено:

1. Banner вверху: «Это событие уже прошло»
2. CTA «Купить билет» -> disabled, текст «Событие завершено»
3. Страница не удаляется (SEO-ценность сохраняется)
4. Карточка НЕ показывается в Related/Anti-Bubble других страниц (freshness gate)
5. JSON-LD `eventStatus` обновляется на `EventScheduled` (прошедшее, но состоявшееся — Google рекомендует оставлять `EventScheduled` для прошедших)
6. Related section на самой странице прошедшего события — показывает будущие события (перенаправление потока)

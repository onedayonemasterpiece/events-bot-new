# Правила розыгрыша двух партнёрских билетов

> **Статус:** продуктовая версия для реализации и последующей публикации.  
> **Организатор проекта:** Максим Никифоров.  
> **Связанная стратегия:** [`README.md`](README.md)

## 1. Приз

Разыгрывается один приз для одного победителя:

- два партнёрских билета в театр;
- билеты передаются лично;
- денежная замена не предусмотрена;
- формулировка «на любой спектакль» не используется;
- конкретный спектакль, дата и условия посещения определяются фактически
  доступными партнёрскими билетами и сообщаются победителю до передачи.

## 2. Срок и момент розыгрыша

Действия для eligibility принимаются до:

```text
31 августа 2026 года, 18:00:00
Europe/Kaliningrad
```

Технически snapshot учитывает записи с серверным временем строго раньше
`2026-08-31T18:00:00+02:00`.

В 18:00:

1. прекращается начисление артефактов и бонусных шансов;
2. формируется неизменяемый eligible snapshot;
3. автоматически выбираются победитель и один резервный участник;
4. победителю отправляется персональное письмо.

## 3. Кто участвует

Участник попадает в пул, если до cutoff одновременно выполнены условия:

1. сайт был открыт через приглашение фокус-группы;
2. подтверждён email или выполнен вход через Яндекс;
3. серверная registration участника завершена успешно;
4. найдено не менее 10 из 12 артефактов версии `focus-eggs-v1`;
5. оставлена хотя бы одна оценка страницы `0–10`;
6. нет подтверждённой массовой автоматизации, повторного использования чужой
   identity или эксплуатации ошибки для искусственного начисления результатов.

Общий `service_nps` полезен исследованию, но не является дополнительным условием
попадания в пул.

Локальная метка без подтверждённого email/Яндекса позволяет тестировать сайт, но
не создаёт запись в пуле розыгрыша.

## 4. Артефакты

В первой версии ровно 12 артефактов:

```text
FG-E01, FG-E02, FG-E03, FG-E04, FG-E05, FG-E06,
FG-E07, FG-E08, FG-E09, FG-E10, FG-E11, FG-E12
```

Порог `80%` равен:

```text
ceil(12 × 0.80) = 10
```

Один `artifact_id` засчитывается одному participant один раз. Reload, повторный
клик, повторная доставка и другое устройство не создают вторую находку.
Eligibility использует server-owned idempotent receipts. LocalStorage может
показывать прогресс, но не является доказательством для розыгрыша.

Если артефакт был технически недоступен существенную часть программы, изменение
знаменателя допускается только заранее, одинаково для всех и через новую
`collection_version`. После cutoff знаменатель не меняется.

## 5. Число шансов

Каждый eligible participant получает от 1 до 3 записей в случайном пуле:

| Условие | Шансы |
|---|---:|
| Выполнены базовые eligibility conditions | `+1` |
| Есть хотя бы один принятый непустой текстовый отзыв | `+1` |
| Есть хотя бы один принятый screenshot | `+1` |
| Максимум | `3` |

Один feedback, содержащий и текст, и screenshot, закрывает оба бонусных условия.

Не влияют на число шансов:

- значение оценки страницы;
- значение общего NPS сервиса;
- положительность или критичность текста;
- длина текста сверх факта непустого ответа;
- количество текстовых сообщений после первого;
- количество screenshots после первого;
- лайки, покупки, share и скорость выполнения;
- ручная оценка «качества» отзыва оператором.

Whitespace-only, удалённый до сохранения файл, технический дубль и повтор одного
`client_request_id` бонуса не дают.

## 6. Автоматический выбор

Перед выбором создаётся snapshot:

```text
program_id
rules_version
collection_version
cutoff_at
eligible participant public IDs
chance_count каждого participant: 1..3
snapshot hash
```

Защищённый workflow:

1. проверяет cutoff и неизменяемость snapshot;
2. строит weighted pool по `chance_count`;
3. выбирает одну запись случайным seed;
4. выбирает отдельного резервного участника, исключая победителя;
5. сохраняет receipt с snapshot hash, seed commitment/result и public IDs;
6. при повторе того же snapshot возвращает тот же результат;
7. не пишет email и другие персональные данные в GitHub artifact.

Новый выбор допустим только через отдельный `promote_reserve` после истечения
срока ответа победителя или документированного отказа.

## 7. Письмо победителю и срок ответа

Победителю сразу после розыгрыша отправляется письмо на подтверждённый email.

В письме:

- поздравление;
- информация о двух партнёрских билетах;
- просьба подтвердить получение письма;
- способ согласовать личную передачу;
- точный крайний срок ответа.

На ответ даётся **3 календарных дня** с момента успешной отправки письма. Если
ответ не получен, приз переходит к резервному участнику, которому отправляется
аналогичное письмо с собственным трёхдневным сроком.

Шаблон письма подготавливается ближе к розыгрышу, но protected dry run на
тестовый mailbox должен пройти до 31 августа.

## 8. Письмо всем участникам

После того как финальный победитель подтвердил получение и готовность принять
приз, всем подтверждённым участникам отправляется одно письмо:

- благодарность за участие в фокус-группе;
- краткое сообщение о том, что розыгрыш завершён;
- победитель в согласованной форме;
- что команда узнала и что будет происходить с сайтом дальше;
- способ отказаться от последующих необязательных писем, если они планируются.

По умолчанию для рассылки используется безопасная форма `Имя + первая буква
фамилии`. Полное имя указывается только с согласия победителя.

Письмо отправляется один раз идемпотентным batch. Неподтверждённые пользователи
его не получают, поскольку у программы нет проверенного адреса.

## 9. Что видит участник

Достаточно показывать:

- `найдено N из 12`;
- `для розыгрыша нужно 10`;
- подтверждён ли email/Яндекс;
- оставлена ли минимум одна оценка страницы;
- есть ли бонус за текст;
- есть ли бонус за screenshot;
- итог: `ваших шансов — 1/2/3`;
- версию правил и cutoff.

Публичный leaderboard не нужен. Чужие оценки, feedback, email и прогресс не
показываются.

## 10. Остановка и исправления

До cutoff правила могут быть исправлены только через новую `rules_version` с
понятным объяснением, опубликованным для всех участников. После snapshot нельзя:

- менять threshold 10/12;
- менять число шансов;
- удалять критические отзывы из бонуса из-за их содержания;
- подменять победителя вне reserve procedure;
- заменять приз без уведомления участников.

Если розыгрыш невозможно провести, всем подтверждённым участникам отправляется
отдельное объяснение. Молчаливое прекращение программы недопустимо.

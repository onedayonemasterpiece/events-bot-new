# Информационные партнёры

> **Status:** draft + static-site preview page  
> **Surface:** `site/src/pages/partners/index.astro` → `/partners/`  
> **Related:** `docs/features/promo-campaigns/README.md`, `docs/features/static-site-pages/README.md`, `docs/features/unsigned-personalization/README.md`

## Задача

Фича фиксирует статус **информационного партнёра** как производную от промо-кампаний и партнёрского статуса. В продукте это отдельная страница персонализированного static-first сайта «Полюбить Калининград Анонсы», где пользователь видит полный список партнёров как логотипы организаций/институций.

Страница нужна не как рекламный баннер в ленте событий, а как прозрачный справочник: кто помогает распространять анонсы, фестивальные программы и образовательные события.

## MVP-страница

- URL: `/partners/`.
- Навигация: ссылка `Инфопартнёры` в подвале сайта; мобильный drawer тоже может показывать ссылку как сервисную навигацию.
- Контент: компактная logo-first доска партнёров с заголовком `Полюбить Калининград Анонсы выступает информационным партнёром организаций`. Подпись рендерится только там, где без неё не считывается конкретный партнёрский контекст; для узнаваемых логотипов вроде «Знание» и «Акт Опус» подпись можно не показывать. Подпись не должна быть категорией вроде «маршруты», «лекции» или «театр»: это конкретный контекст партнёрства. Длинное описание, поясняющий prose-блок, категории и отдельный CTA «Сайт партнёра» на странице не нужны.
- Ссылка: вся плитка партнёра является внешней ссылкой на сайт партнёра; отдельную ссылку внутри плитки не рендерим, чтобы не дублировать действие и не раздувать карточку.
- Grid: это плоская logo-board / bento-grid, а не набор тяжёлых карточек/плашек: без заливок, декоративных теней, border-card treatment и рекламных выделений. Сетка учитывает аспект логотипа (`wide`, `tall`, `compact`, `square`) и разрешает партнёру занимать соседние ячейки справа/снизу через span-переменные; высота рядов фиксирована, поэтому подпись не должна растягивать сетку — логотип сначала нормализуется внутри выбранного span, подпись вторична. Модель размещения: для каждого партнёра оцениваем варианты `colSpan × rowSpan` по трём штрафам — mismatch логотипа к доступному aspect ratio, fit подписи и `visualWeight` исходного логотипа. Затем фиксируем build-time greedy/backtracking placement для 4-col mobile и 8-col tablet/desktop. Текущий contract: mobile 4×3 без пустых ячеек — hero `80 историй 2×2` первым блоком слева, справа от него `Знание 2×1` и ниже `Акт Опус 2×1`, третья строка `Кантата 2×1` + КППК `2×1`; desktop 8×2 — `80 историй 2×2`, `Знание 4×1`, КППК `2×1`, ниже `Кантата 3×1` и `Акт Опус 3×1`.
- SEO/robots: текущий preview layout остаётся `noindex,nofollow,noarchive`; внешние ссылки партнёров дополнительно идут с `rel="nofollow noopener noreferrer"`.
- Логотипы: предпочтительно SVG, если источник это позволяет; если исходник только raster, browser-facing primary должен быть WebP, а PNG допускается как fallback/QA. Source/provenance фиксируется рядом с ассетами в `site/src/assets/partners/source/`.
- Данные: стартовый список хранится в `site/src/data/info-partners.ts`; в будущем его можно вывести из партнёрского статуса в promo/domain-модели.

## Связь с промо-кампаниями и статусом

Информационный партнёр — это отдельный публичный статус, который может быть привязан к:

1. **Организации**: институция, перевозчик, образовательный партнёр, фестивальный оргкомитет.
2. **Промо-кампании**: конкретная кампания может повышать видимость событий партнёра, но страница партнёров не должна автоматически становиться лентой промо.
3. **Событиям/сериям**: событие может получить бейдж/упоминание партнёра только если это явно задано в campaign/status metadata, а не выводится из совпадения названий.

Отдельно утверждённый static-site MVP для транспорта является явным scoped campaign rule: event-detail страницы событий в Светлогорске/Зеленоградске могут показывать маркированный модуль `Партнёрский маршрут · АО «КППК»`. Он не выводится из названия организатора и не превращает общий partner manifest в event attribution. Канонический контракт: `docs/features/static-site-pages/event-transport-schedule.md`.

Пока MVP-страница статическая. Следующий этап — добавить модель `info_partner`/`partner_status` или расширить существующие promo metadata так, чтобы:

- партнёр мог быть активным/архивным;
- порядок карточек был управляемым;
- логотип и public URL проходили валидацию;
- публичная страница собиралась из export manifest без ручного редактирования Astro-кода.

## Acceptance checklist

- `/partners/index.html` появляется в static build.
- Footer содержит ссылку `Инфопартнёры` на `/partners/`.
- `sitemap.xml` содержит `/partners/` для preview-проверки; `robots.txt` всё ещё запрещает индексацию preview.
- Все внешние ссылки партнёров имеют `rel="nofollow noopener noreferrer"`.
- Страница не использует OpenAI image generation; логотипы взяты из локальных/официальных SVG или WebP-primary raster sources с PNG fallback.
- Grid сохраняет разные аспекты логотипов: wordmark КАНТАТА/Акт Опус/Знание широкие на tablet/desktop, `80 историй` использует вертикальный hero-lockup и `grid-row` span 2; фиксированный `grid-auto-rows` и фиксированные logo/caption frames не дают подписи задавать высоту ячеек, а крупность логотипа выводится из занятого span.
- Mobile `/partners/` использует компактный 4-колоночный bento grid без one-column fallback; occupancy должен оставаться плотным, без пустых ячеек в текущем наборе партнёров. КППК получает 2×1, потому что реальный RZD mark в 1×1 становится визуально слишком лёгким.
- Публичные подписи являются партнёрскими caption-строками, а не категориями: строки `Пригородные маршруты`, `Просветительские события`, `Фестиваль 80-летия`, `Лекции и музыка`, `Театр и премьеры` запрещены. У `Знания` и `Акт Опус` подписи не рендерятся.
- КППК рендерится как official-site RZD mark + подпись `АО «КППК»` без неверного публичного label `КППК / РЖД`.
- Кантата рендерится с подписью `Образовательная программа фестиваля`.
- `80 историй о главном` рендерится с подписью `Просветительский фестиваль к 80-летию Калининградской области`.
- Вёрстка остаётся плоской logo-board: без тяжёлых card borders/backgrounds/shadows и без декоративных radial-highlight плашек.
- Партнёрская плитка — единственная кликабельная сущность для внешнего перехода; отдельный текст `Сайт партнёра`/CTA не должен появляться в HTML.
- Документация и `CHANGELOG.md` синхронизированы с кодом.

## Production gates

1. Получить/подтвердить официальные логотипы и право использования для новых партнёров.
2. Держать logo assets в стабильном месте (`site/public/assets/partners/` или CDN bucket) и фиксировать fallback alt/name/provenance.
3. Решить источник правды для статуса: расширение promo metadata или отдельная таблица/manifest.
4. Добавить админский/операционный процесс обновления партнёров без правки layout.
5. Прогнать `npm run build:preview && npm run check:preview` перед публикацией preview.
